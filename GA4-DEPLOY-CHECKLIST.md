# Что нужно сделать, чтобы GA4 заработала

Файл `analytics.py` уже переписан и лежит в проекте. Дальше — только деплой и проверка.
Идите по шагам сверху вниз, каждый шаг заканчивается конкретной проверкой.

---

## Шаг 0. Понять, что именно сейчас сломано

Три вещи, которые нужно держать в голове:

1. **Код на проде старый.** Streamlit Cloud деплоит ветку `main`. Ваш фикс лежит в
   ветке `agent/fix-ga4-tracking` и не запушен. Пока не сделаете merge в `main` —
   на сайте ничего не изменится, сколько бы вы ни правили файлы локально.
2. **Старая архитектура не работала принципиально.** gtag жил внутри одноразовых
   iframe'ов Streamlit (`about:srcdoc`), которые уничтожаются при каждом
   перерисовывании страницы. Новый код поднимает gtag в главном документе.
3. **Стандартные отчёты GA4 отстают на 24–48 часов.** Проверять надо в
   **Realtime** и **DebugView**, а не в «Отчётах». Очень часто «аналитика не
   работает» — это просто рано смотреть.

## Шаг 1. Проверить локально (10 минут)

Запустите приложение у себя:

```bash
cd G:\5_Ecolytica\1_Programs\5_nvos\nvos_calculator_ecolytica
.venv\Scripts\activate
streamlit run app.py
```

Откроется `http://localhost:8501`. Дальше — **F12** (DevTools).

### 1.1. Вкладка Console

Вставьте и выполните:

```js
window.__ecolyticaGtag
```

Должно вернуться `true`. Это флаг того, что мостик отработал и gtag поднялся
в главном документе. Если `undefined` — компонент не отрендерился, смотрите ошибки
в консоли.

Затем:

```js
document.querySelectorAll('script[src*="gtag/js"]').length
```

Должна быть **ровно 1**. Если 0 — скрипт заблокирован (блокировщик рекламы).
Если больше 1 — что-то не так с флагом дедупликации.

### 1.2. Вкладка Network

1. В фильтре введите `collect`.
2. Перезагрузите страницу (Ctrl+F5).
3. Должен появиться запрос на `google-analytics.com/g/collect` со статусом
   **204** или **200**.
4. Кликните по нему → **Payload** / строка запроса. Найдите параметры:
   - `en=page_view` — имя события,
   - `tid=G-KBKGG5TXDT` — ваш Measurement ID,
   - `dl=http://localhost:8501/` — реальный адрес страницы (раньше здесь был
     подставленный вручную URL, это и была одна из проблем).

**Если запроса нет вообще** — почти наверняка блокировщик рекламы. Откройте
в режиме инкогнито с отключёнными расширениями и повторите.

### 1.3. Проверить события

Не перезагружая страницу, следите за фильтром `collect` и по очереди:

| Действие | Ожидаемое событие (`en=`) |
|---|---|
| Загрузить xls-файл с нормативами | `file_uploaded`, затем `xls_parse_success` |
| Нажать «Скачать Excel» | `excel_download` |
| Кликнуть ссылку Telegram/ВК в сайдбаре | `social_click` |
| Раскрыть блок «Сообщить об ошибке» | `feedback_open` |

Каждое должно дать отдельный запрос на `/g/collect`.

## Шаг 2. Закоммитить и запушить

**Важно:** в `git status` сейчас помечены изменёнными 9 файлов, но реально
изменён только `analytics.py`. Остальные восемь — это ложное срабатывание из-за
переводов строк (CRLF/LF). Поэтому добавляйте файл точечно, а не `git add .`:

```bash
git add analytics.py GA4-DEPLOY-CHECKLIST.md
git commit -m "Перенести gtag в родительский документ Streamlit"
git push -u origin agent/fix-ga4-tracking
```

Чтобы CRLF-шум больше не мешал, один раз выполните:

```bash
git config core.autocrlf true
```

## Шаг 4. Дождаться редеплоя Streamlit Cloud

1. Откройте https://share.streamlit.io и найдите приложение `ecolytica-nvos`
2. После пуша в `main` оно должно перезапуститься само в течение 1–2 минут
3. Если не перезапустилось — **Manage app** → **⋮** → **Reboot app**
4. В логах (Manage app → нижняя панель) убедитесь, что нет ошибок импорта

**Заодно проверьте секреты:** Manage app → **Settings** → **Secrets**.
Если там задан `GA4_MEASUREMENT_ID`, он перекрывает значение в коде. Убедитесь,
что это именно `G-KBKGG5TXDT`. Если поле пустое — ничего страшного, код возьмёт
ID из себя (`analytics.py`, константа `_DEFAULT_GA4_MEASUREMENT_ID`).

## Шаг 6. Проверить в GA4

### 6.1. Realtime (данные появляются за 10–60 секунд)

1. https://analytics.google.com → ваш ресурс
2. **Отчёты** → **В реальном времени**
3. Держите открытой вкладку с калькулятором, покликайте по нему
4. Должны увидеть: 1 пользователь, события `page_view`, `social_click` и т.д.

### 6.2. DebugView (детальнее, видно параметры каждого события)

Самый быстрый способ включить:

1. Установите расширение **Google Analytics Debugger** для Chrome
2. Включите его на вкладке с калькулятором, перезагрузите страницу
3. GA4 → **Администратор** → **DebugView**
4. Увидите поток событий в реальном времени с полными параметрами

Здесь же проверьте, что у `social_click` приходят параметры `network`
(`telegram` / `vk`) и `source` (`sidebar` / `results`).

## Шаг 7. Если в GA4 по-прежнему пусто

Идите по списку сверху вниз — от самого частого к самому редкому.

1. **Блокировщик рекламы / Brave / DNS-фильтр.** Проверьте в чистом инкогнито
   без расширений, лучше с телефона по мобильному интернету.
2. **Не тот Measurement ID.** GA4 → Администратор → **Потоки данных** → откройте
   поток → сверьте `G-XXXXXXX` с тем, что уходит в параметре `tid=` из шага 1.2.
   Если не совпадает — поправьте константу в `analytics.py` или секрет в
   Streamlit Cloud.
3. **Фильтр внутреннего трафика.** GA4 → Администратор → **Настройки данных** →
   **Фильтры данных**. Если есть фильтр «Internal Traffic» в состоянии
   «Активный», он может резать ваши визиты. На время проверки переведите
   в «Тестирование».
4. **Ресурс/поток создан только что.** Новым потокам иногда нужно несколько
   часов, прежде чем данные начнут отображаться корректно.
5. **Смотрите не туда.** Ещё раз: стандартные отчёты («Обзор», «Привлечение»)
   наполняются через 24–48 часов. Первые сутки верить можно только Realtime
   и DebugView.
6. **Запрос уходит, но со статусом ≠ 2xx.** Скопируйте URL запроса `/g/collect`
   и пришлите — разберём по параметрам.

## Шаг 8. Донастроить GA4 (после того, как данные пошли)

Это уже не про починку, а про пользу от аналитики:

1. **Отметить ключевые события.** GA4 → Администратор → **События** → напротив
   `excel_download` и `social_click` включите переключатель «Отметить как
   ключевое событие». Тогда они попадут в отчёты по конверсиям.
2. **Увеличить срок хранения данных.** Администратор → Настройки данных →
   **Хранение данных** → поставьте **14 месяцев** вместо дефолтных 2.
   Дефолт сильно ограничивает исследования.
3. **Исключить свой трафик.** Администратор → Потоки данных → поток →
   **Настроить параметры тега** → **Определение внутреннего трафика** →
   добавьте свой IP. Иначе ваши собственные тесты будут искажать статистику
   при небольшом трафике.
4. **Настроить отчёт по воронке.** Исследования → Исследование воронки:
   `page_view` → `file_uploaded` → `xls_parse_success` → `excel_download`.
   Это покажет, на каком шаге отваливаются экологи, — самое ценное, что
   вообще можно вытащить из этого калькулятора.

## Приложение: что изменилось в коде

| Было | Стало |
|---|---|
| gtag грузился заново в каждом iframe компонента (3–5 копий на страницу) | gtag поднимается один раз в главном документе, флаг `window.__ecolyticaGtag` |
| События уходили из iframe, который Streamlit уничтожал при следующем rerun | События уходят из главного документа через `window.parent.gtag` — rerun им не страшен |
| `page_location` подставлялся вручную, реальный URL был `about:srcdoc` | GA4 берёт настоящий URL страницы |
| `page_view` отправлялся вручную с флагом `send_page_view: false` | `page_view` отправляет сам `gtag('config', ...)`, ровно один раз на загрузку вкладки |
| `transport_type: 'beacon'` (параметр Universal Analytics, GA4 его игнорирует) | Убран |

Публичные функции (`render_page_view`, `queue_event`, `flush_events`,
`render_sidebar_about`, `render_social_button`, `render_feedback`) не изменились,
поэтому `app.py` править не нужно.
